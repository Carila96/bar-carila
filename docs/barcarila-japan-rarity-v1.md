# BarCarila 日本BAR希少度基準 v1

Status: PROVISIONAL calibration specification
Date: 2026-09-04

## 目的

BarCarila の「希少度」を、世界的な知名度やクラシック度ではなく、**日本国内の一般的なBARで、その一杯を実際に注文できる可能性の低さ**として定義し直す。

バーテンダーCarilaは世界中の酒文化を扱うため、この日本BAR希少度で推薦候補を制限しない。

## 基本定義

- `japan_availability_score`: 0-100。日本の一般的なBARでその一杯が成立する可能性。高いほど頼みやすい。
- `japan_rarity_score`: `100 - japan_availability_score`。高いほど日本のBARでは珍しい。
- `confidence`: 0-1。評価根拠の確からしさ。根拠不足時に精密な数値を装わないために保持する。
- `rarity_reason`: UI表示用ではなく、監査・再評価用の短い根拠文。
- `evaluated_at`: 評価日。
- `evidence_version`: 評価基準のバージョン。

## スコアの構成

### 1. 日本BARでの実提供・メニュー普及 45%

最重要。日本国内の実店舗メニュー、BAR向け情報、複数地域・複数業態での提供実績を見る。

- 4: オーセンティックBAR/ショットバー等で広く確認でき、定番として扱われる
- 3: 複数の一般BARで確認できるが、定番中の定番までは言えない
- 2: ホテルBAR、専門店、特定ジャンル店では見かけるが一般BARでは限定的
- 1: 日本国内の提供例はあるがかなり限定的
- 0: 十分な提供実績を確認できない

### 2. 材料・銘柄の国内入手性 25%

日本国内で一般BARが材料を仕入れやすいかを見る。

- 4: 基本スピリッツ、一般的リキュール、一般的ジュース等
- 3: 国内流通は十分あるが全店常備とは言いにくい
- 2: 専門酒販・輸入品としては入手可能
- 1: 限定流通・特定銘柄依存・季節材料依存
- 0: 通常営業での継続調達が難しい

### 3. 日本のバーテンダーにおける標準性 20%

日本バーテンダー協会、国内大手酒類メーカーのスタンダードカクテル資料、国内BAR文化での扱いを根拠にする。

- 4: 国内の標準カクテル資料で明確に定番
- 3: 広く認知されているクラシック/一般カクテル
- 2: 経験あるバーテンダーなら知っている可能性が高いが標準性は弱い
- 1: 専門領域・海外文化寄り
- 0: 日本の一般BARで標準知識とは扱えない

### 4. 営業上の作りやすさ 10%

特殊器具、長時間仕込み、特殊な生鮮材料、複雑な技法の必要性を見る。

- 4: 通常のBAR設備で即時作成可能
- 3: 一般的なシェーク/ステア/ビルドで作成可能
- 2: 一部の追加材料・設備・仕込みが必要
- 1: 特殊な材料や仕込みが複数必要
- 0: 通常営業での対応がかなり難しい

## Evidence hierarchy

評価は AI の印象だけで決めない。

優先順位:

1. 日本バーテンダー協会など国内の専門団体
2. サントリー等の国内酒類メーカーによるBAR/カクテル資料
3. 現在営業している日本国内のBAR・ホテルBARの実メニュー
4. 国内正規流通・インポーター・酒販情報
5. 補助資料として一般記事

Google検索件数や世界的知名度は、希少度の直接根拠にしない。

## 表示ラベル（暫定）

`japan_rarity_score` を以下の表示へ変換する。

- 0-14: 定番
- 15-29: 比較的よくある
- 30-49: やや珍しい
- 50-69: 珍しい
- 70-84: かなり珍しい
- 85-100: ごく一部の店

数値境界はキャリブレーション後に確定する。

## アペロールスプリッツを境界テストにする理由

世界的には非常に著名なカクテルだが、日本国内ではイタリアン、ホテルBAR、インターナショナル系店舗での掲載が目立つ。一方、日本の一般的なBARでジントニックやギムレットと同程度に普遍的とは言いにくい。

したがって BarCarila で「定番」と表示されるなら基準が世界人気へ引っ張られている可能性が高い。v1 では「やや珍しい」側に置き、今後の実店舗サンプル調査で再調整する。

## 酒名・銘柄・バリアントの扱い

同じカテゴリでも具体性が増すほど提供可能性は変わる。

例:

- `ラフロイグ` と `ラフロイグ カスクストレングス` は別評価可能
- `ジントニック` と `特定クラフトジン + 特定トニック指定` は別評価可能

D1では将来的に `drink_id`, `brand_id`, `variant_id` を分離できる構造を想定する。MVPでは少なくとも canonical name と aliases を持つ。

## 保存型の原則

BarCarilaの推薦ごとにWeb検索して希少度を決めない。

1. 調査・評価時に evidence を確認
2. 確定した希少度を D1 の酒マスターへ保存
3. BarCarilaの推薦時は D1 の保存値を参照
4. 一定期間ごと、またはユーザー/運用者から違和感報告があった酒だけ再評価

これにより速度、再現性、APIコスト、説明可能性を担保する。

## 次段階

1. 代表50-100杯へキャリブレーションを拡張
2. ジン/ウォッカ/ラム/テキーラ/ウイスキー/ブランデー/ワイン/リキュールを偏りなく含める
3. 日本のBAR実メニューを複数地域・複数業態から追加確認
4. 閾値を調整し v1.0 を CONFIRMED にする
5. D1 `drinks` マスター設計・投入
6. BarCarilaの希少度表示と推薦ロジックをD1参照へ切替
7. UIの説明文・詳細表示は後工程で調整
