# Bartender Carila service plan

最終更新: 2026-10-10
状態: 仮説 / 未確定

## 現在の位置づけ

Bartender Carila は、BARのカウンターでバーテンダーと話す感覚を目指した会話機能である。
テキスト会話とRealtime音声会話はすでに実装されているが、サービスとしての価値設計、無料範囲、有料範囲、価格、継続課金条件はまだ確定していない。

現段階では「完成した有料サービス」として扱わない。利用者に料金を請求する前に、実機Acceptance、会話品質、利用継続性、API原価、無料体験から有料化する価値の境界を確認する。

## 将来の収益化仮説

- 無料側: BAR CARILA本体のお酒提案・検索・閲覧など、入口として使える体験を維持する候補。
- 有料側候補: Bartender Carilaとの継続的なテキスト会話、Realtime音声会話、将来の記憶・常連体験など。
- 過去に月額1,000円程度の案があったが、現時点では価格を確定しない。
- Stripe等の課金実装も、無料/有料境界と価格が決まるまでは開始しない。

## 暫定Trial制限

課金前でもAPI原価が無制限に発生する状態は避ける。そのため、現在の公開試用版にはサービス仕様ではなく「コストガード」として以下の暫定上限を置く。

- テキスト会話: 1ブラウザあたり20 user turn / 日
- Realtime音声会話: 1ブラウザあたり2 session / 日
- Realtime音声会話: 1 session 最大5分
- 日次リセット基準: Asia/Tokyo 00:00

テキスト/音声の日次回数はCloudflare D1の `carila_usage_daily` で匿名ブラウザID単位に保持する。ブラウザIDはHttpOnly cookieで発行し、raw IPは保存しない。

この制限は料金プランの無料枠を意味しない。サービス設計が決まり次第、実測原価・継続率・課金方針に合わせて置き換える。

## 現方式の限界

アカウント認証が未導入のため、cookie削除や別ブラウザ利用まで完全には防げない。音声の5分制限も通常UIでは停止するが、現在のWebRTC構造では認証済みアカウント単位の厳密なサーバー強制終了ではない。

したがって現在の仕組みは「一般利用での無制限消費を防ぐコストガード」であり、不正利用耐性の最終形ではない。

本格課金前には、少なくとも以下を再設計する。

- ユーザー/匿名IDの正式な識別方法
- 無料枠と有料枠
- テキスト/音声それぞれの原価計測
- 音声時間の厳密なサーバー側制御
- Stripe等のentitlement連携
- 解約/返金/利用上限表示
- Privacy/Termsへの必要な追記

## 次に決めること

1. Bartender Carilaでユーザーがお金を払う価値は何か。
2. 無料でどこまで体験させるか。
3. 有料化するなら月額・従量・併用のどれが適切か。
4. 音声会話を有料価値の中心にするか、テキスト会話にも独立価値を持たせるか。
5. 会話記憶・常連体験をどこまで持たせるか。
